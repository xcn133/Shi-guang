二、关键决策与理由
================================================================================

【决策1】选择 Vue 3 + Vite 5
  理由：
  - Vue 3 Composition API 更适合复杂交互逻辑
  - Vite 5 启动速度快，开发体验好
  - 生态成熟，社区支持完善

【决策2】使用 Pinia 而非 Vuex
  理由：
  - Pinia 更轻量，API 更简洁
  - TypeScript 支持更好
  - Vue 3 官方推荐

【决策3】选择 ngrok 而非其他内网穿透工具
  理由：
  - 配置简单，无需修改代码
  - 支持自定义域名（付费版）
  - 稳定性高，免费版够用
  - 有图形界面和命令行两种方式

【决策4】使用 Canvas 实现涂鸦板
  理由：
  - 原生性能好，无需额外库
  - 支持触摸和鼠标绘制
  - 可以获取绘制路径数据用于评分

【决策5】降级 TypeScript 到 5.2.2
  理由：
  - 解决 vue-tsc 编译错误
  - Node.js v24 与 TypeScript 5.3+ 存在兼容性问题
  - 5.2.2 稳定且支持所有需要的特性

【决策6】端口从 5173 → 5174 → 5176 → 5179
  理由：
  - 每次重启端口被占用自动递增
  - 最终稳定在 5179 端口

五、已排除的错误方向
================================================================================

【错误1】使用 TypeScript 5.3+
  问题：Node.js v24 与 TypeScript 5.3+ 不兼容
  错误信息：Search string not found: "/supportedTSExtensions = .*(?=;)/"
  解决方案：降级到 TypeScript 5.2.2
  教训：新版本可能存在兼容性问题，使用稳定版本

【错误2】vite.config.ts 路径别名使用字符串
  问题：使用 '@': '/src' 而非 path.resolve
  影响：在某些环境下路径解析失败
  解决方案：
    import path from 'path'
    alias: {
      '@': path.resolve(__dirname, './src')
    }
  教训：使用绝对路径更可靠

【错误3】HighFiveButton.vue 文件格式错误
  问题：文件开头有多余的 HTML 内容
  错误信息：SyntaxError: Unexpected token '...'
  解决方案：删除多余的 HTML，确保 <template> 在第一行
  教训：文件格式要规范，避免编辑器误操作

【错误4】未配置 server.allowedHosts
  问题：ngrok 域名被 Vite 阻止
  错误信息：Blocked request. This host is not allowed.
  解决方案：在 vite.config.ts 添加：
    server: {
      allowedHosts: [
        'anew-collector-unlawful.ngrok-free.dev',
        '.ngrok-free.dev'
      ]
    }
  教训：开发环境安全限制需要手动配置白名单

【错误5】ngrok 重复启动同一端点
  问题：尝试启动已在运行的 ngrok 端点
  错误信息：ERROR: failed to start tunnel: The endpoint is already online (ERR_NGROK_334)
  解决方案：
    - 访问 https://dashboard.ngrok.com/tunnels 停止旧隧道
    - 或使用新的随机域名
  教训：ngrok 免费版每个端点只能运行一个实例

【错误6】端口不断变化
  问题：开发服务器端口从 5173 → 5174 → 5176 → 5179
  原因：每次重启端口被占用，Vite 自动递增
  解决方案：
    - 关闭占用端口的进程
    - 或接受新端口，同步更新 ngrok
  教训：开发过程中端口冲突很常见，要灵活应对
